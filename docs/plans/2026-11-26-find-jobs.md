# Plan: Find jobs from real sources

Status: phases 0 to 2 done, 2026-11-26. Next: phase 3.

Find jobs said "coming soon" until now. This plan fills it with real jobs from company job boards, refreshed on a
schedule and ranked by match. Job sites where people keep a profile (LinkedIn, eJobs) have no API and forbid
scraping, so their jobs keep coming in through **Add a job**, made one click. The sources and their terms are in
[job-sources.md](../job-sources.md).

## Decisions

| Question | Proposal |
| --- | --- |
| Where jobs come from | Company job boards (ATS), from a list of companies kept in the repo; remote job boards later |
| Which jobs are kept | Jobs in Romania only for now, remote ones included when they are based in Romania; in the areas Find jobs filters on (DevOps, Backend, Data, Sysadmin) |
| Requirements | The rules read them on import; Claude's analysis runs when the person saves the job, as for added jobs |
| How often | Every 6 hours, one request per second per host |
| LinkedIn, eJobs | Not imported; a **Send to Hoply** bookmarklet opens Add a job with the page's text |

## Data

| Column on `jobs` | Use |
| --- | --- |
| `origin`, `external_id` | the platform and its job id; unique together, so a run updates instead of duplicating |
| `board` | the company's board, to close the jobs it stops listing |
| `posted_at`, `last_seen_at` | newest first; when the board last listed the job |
| `closed_at` | set when the board's list no longer has the job (a board that lists nothing closes nothing); closed jobs leave Find jobs but stay for applications |

Imported jobs have `source: import` and no owner, so everyone sees them, like the catalog.

## Rules for the importer

- A generic User-Agent and nothing about the person in any request.
- One request per second per host. On 429 the importer backs off, and a failing board never stops the others.
- Every job keeps its link to the original, with attribution where the source asks for it.
- Tests use recorded answers in `testdata/`, with no network calls, like the cv service's fake CLI.
- Each board's run is logged: listed, kept, new and closed jobs, or its error.
